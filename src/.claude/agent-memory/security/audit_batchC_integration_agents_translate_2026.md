Verified 2026-07-06 (read-only pass, no edits) against 7 "Batch C" items from the roadmap ([[project_helpdesk_modules_roadmap]]) across HelpdeskIntegration, HelpdeskAgents, HelpdeskChatFlow, HelpdeskHelpcenter, HelpdeskCompliance, HelpdeskTranslate.

**YA-RESUELTO (5/7):**
1. **Integration OTP reuse** — `CustomerIdentityVerificationService::requestCode()` (`modules/HelpdeskIntegration/app/Services/CustomerIdentityVerificationService.php:36`) invalidates all prior pending codes for the customer (`expires_at = now()->subSecond()`) before minting a new one. Only one live OTP per customer at a time; `confirmCode()` also burns the code after `MAX_CODE_ATTEMPTS` (5).
2. **Agents `database` tool arbitrary SELECT** — `ToolExecutionService::executeDatabaseTool()` (`modules/HelpdeskAgents/app/Services/ToolExecutionService.php:140`) enforces: SELECT-only, blocks `;`/`--`/`/*` (multi-statement/comment injection), and a fail-closed table allowlist (`config('helpdeskagents.tools.allowed_tables')`) extracted via regex on FROM/JOIN — rejects if any referenced table isn't allow-listed. LLM-supplied `$arguments` go through `DB::select($sql, $arguments)` as parameterized bindings, not concatenation.
3. **ChatFlow import() DoS via unbounded nodes** — `ChatFlowsController::import()` (`modules/HelpdeskChatFlow/app/Http/Controllers/ChatFlowsController.php:254`) checks `count($data['nodes']) > config('helpdeskchatflow.import.max_nodes', 500)` (and edges capped at 4x that), plus per-node type/id shape validation and re-use of the publish validator.
4. **Helpcenter apiArticleFeedback vote spam** — `HelpcenterWidgetController::apiArticleFeedback()` → `HelpcenterWidgetService::recordFeedback()` (`modules/HelpdeskHelpcenter/app/Services/HelpcenterWidgetService.php:175`) dedups by `hd_voter_id` cookie (1yr) OR ip_hash against `HelpCenterArticleVote`, backed by unique indexes migration. Already has `tests/Feature/HelpCenterVoteTest.php`.
6. **Translate manual routes bypass integration toggle** — `modules/HelpdeskTranslate/routes/managers.php:22` now wraps `/translate`, `/conversations/items/{item}/translate`, and `/detect-language` in `Route::middleware('integration.enabled:translate')`, each also with `throttle:60,1`. Inline comment documents this was the historical bug (only automatic listeners respected the toggle) and it's now fixed to match HelpdeskDocument/HelpdeskCompliance pattern.

**FALSO-POSITIVO (1/7):**
5. **Compliance `moduleReady()` ignoring integration toggle** — `ProcessComplianceCascadeJob::moduleReady()` (`modules/HelpdeskCompliance/app/Jobs/ProcessComplianceCascadeJob.php:119`) deliberately checks only `Module::isEnabled()` + `class_exists()`, NOT `helpdesk_tickets_enabled()`/`helpdesk_chatflow_enabled()`. This is an explicit, documented design decision (inline comment: "A PROPÓSITO ... Saltarse el borrado por un switch de UI sería una violación de GDPR, no una mejora"). A GDPR delete cascade must run regardless of an admin's UI toggle. Do not flag this again as a bug.

**REAL (1/7) — open gap:**
7. **Translation cache retains customer PII past GDPR hard-delete** — `modules/HelpdeskTranslate/app/Models/TranslationCache.php` (table `helpdesk_translation_cache`) stores `text_source`/`text_translated` keyed only by `hash(provider|source|target|text)` — no `customer_id`/`conversation_id` link, no TTL enforcement, no scheduled purge. Written by `CachedTranslator` (`app/Services/CachedTranslator.php:44-76`). The ONLY purge mechanism is `TranslateSettingsController::clearCache()` (`app/Http/Controllers/Settings/TranslateSettingsController.php:111`) — a fully manual, admin-triggered, all-or-nothing delete of the entire cache table. `ProcessComplianceCascadeJob` (HelpdeskCompliance) has NO handler for HelpdeskTranslate — grepping the whole HelpdeskCompliance module for "Translat" only matches the ServiceProvider, no compliance handler exists.
   - **Fix (minimal)**: add a `TranslationCacheComplianceHandler` invoked from `ProcessComplianceCascadeJob::handle()`, OR add a scheduled command that purges rows by `last_used_at` age (TTL). Since cache entries aren't linked to a customer, per-customer targeted purge is hard without adding a customer/conversation reference at write time in `CachedTranslator`.
   - **Test**: feature test that seeds `TranslationCache` with customer-originated text, triggers a GDPR hard-delete, and asserts the cache row is gone (or asserts TTL-based purge via a scheduled command test).
